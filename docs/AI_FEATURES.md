# Snowflake AI 功能提案 ❄️

本方案旨在为 **Snowflake** 注入人工智能能力，通过 LLM（大语言模型）、OCR 和行为分析，将传统的财务管理转化为智能的个人财务助理。

---

## 1. 核心创意功能 (Core AI Concepts)

### 1.1 自然语言智能记账 (NLP Entry)
*   **交互方式**：用户输入一句话，如“中午在麦当劳吃汉堡花了 55 元”。
*   **AI 处理**：解析为结构化数据：
    *   `date`: 2026-03-14
    *   `amount`: 55
    *   `category`: 餐饮
    *   `merchant`: 麦当劳
*   **进阶**：支持语音直接转账单。

### 1.2 拍照识单与明细拆分 (Multi-modal OCR)
*   **场景**：拍摄超市长小票。
*   **AI 处理**：不仅识别总金额，还能自动根据小票条目拆分支出。例如：将一张 500 元的账单拆分为“食品 (300元)”和“家居 (200元)”。

### 1.3 财务“天气预报” (Predictive Forecasting)
*   **场景**：基于历史支出预测未来。
*   **功能**：AI 会发出提醒：“预报：下周将有房租扣款，预计余额将进入‘寒潮’，建议本周末减少大额娱乐支出。”

### 1.4 消费情绪分析 (Emotional Insights)
*   **场景**：结合记账时的心情标签。
*   **分析**：AI 定期生成报告：“你 40% 的不必要支出发生在深夜或心情焦虑时，这被称为‘补偿性消费’。”

---

## 2. 模糊商家名解析方案 (Obscure Merchant Handling)

针对信用卡账单中常见的模糊代码（如 `SQ *`, `TST *`, `AMZN MKTP`），AI 提供以下策略：

### 2.1 商家“去掩码” (Normalization)
*   **逻辑**：LLM 识别收单机构前缀。
*   **转换**：`SQ *LITTLE BEAN` -> **Little Bean Coffee**。

### 2.2 联网增强搜索 (Web-Enhanced RAG)
*   **逻辑**：当本地知识库无法识别代码（如 `ZPR* 9876`）时，AI 自动调用搜索引擎查找该代码对应的真实商家及官方 Logo。

### 2.3 上下文推理 (Contextual Inference)
*   **逻辑**：结合交易的时间、地点和金额大小。
*   **示例**：深夜 11 点在模糊地址发生的 50 元支出，且附近有加油站，AI 会推测为“交通/加油”。

## 3. 复杂复合商家分类策略 (Complex Case Study)

**案例：東急　二子玉川ライズショッピングセンター (东急 二子玉川 Rise 购物中心)**

这类大型购物中心消费内容多样，AI 采用以下分层分类法：

1.  **金额判定法**：
    *   < 2000 JPY: 推测为「餐饮/咖啡」。
    *   3000 - 15000 JPY: 推测为「超市/百货」。
    *   > 20000 JPY: 推测为「购物/电子产品」。
2.  **位置/时间交叉验证**：如果手机定位在影院停留超过 2 小时，自动归类为「娱乐/电影」。
3.  **智能引导 (Smart Prompt)**：AI 主动提问：“看到您在 Rise 有一笔消费，是在吃午饭还是在看电影？”引导用户一键精准分类。

## 4. 技术实现建议 (Implementation)

1.  **API 集成**：推荐接入 OpenAI GPT-4o-mini 或 Claude 3 Haiku，平衡成本与解析精度。
2.  **向量数据库 (Vector DB)**：存储用户的历史消费习惯，实现个性化的“模糊映射”。
3.  **后端处理流**：
    *   用户输入 -> LLM 解析 -> 合法性校验 -> 写入数据库。
    *   信用卡文件上传 -> 批量提取模糊名 -> LLM 批量解析 -> 汇总给用户确认。
